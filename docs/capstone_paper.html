01

Abstract

Which top‑ranking search pages are underperforming on clicks, and can that be flagged automatically rather than found by manual audit?

This project aggregates daily impression, click, and position metrics per page from the FlyRank internship warehouse, engineers a click‑through‑rate (CTR) feature set, and defines a binary refresh‑need label combining low CTR with a strong ranking position. A Random Forest classifier is trained against a majority‑class baseline on a stratified 80/20 split. On the sample pulled for this run, no page satisfied the compound label threshold at once, so the classifier's ranking ability could not be evaluated against true positives — a result that speaks more to how the thresholds and sample size interact than to the model itself. The practical takeaway is about tuning the label definition and traffic filter before the next iteration, not about deploying this model as‑is.

02

Introduction

Organic search teams have limited hours and two competing places to spend them: rewriting metadata and on‑page content for pages that already rank, or building new content from scratch. Pages that hold a strong position but earn a low share of the clicks they should are the clearest case for the first option — the ranking work is already done, only the click‑through is broken.

Decision this supports

Which existing top‑10 pages should go on the metadata/title‑and‑description rewrite queue this cycle, instead of the new‑content backlog.

04

Methodology

Core assumption: a page holding a top‑10 position with a sub‑2% CTR is under‑capturing the clicks its ranking has already earned, and is a metadata‑refresh candidate rather than a new‑content one.

Feature set

avg_impressions, avg_clicks, avg_position, ctr

Label definition

needs_refresh = 1 if CTR < 2% AND avg_position ≤ 10, else 0

Validation design

Stratified 80/20 train/test split against a majority‑class dummy baseline, same split for both models.

Leakage control

All aggregates and thresholds were computed once, before the split, so the same definitions apply identically to train and test.

06

Limitations & honest framing

  • Data scope: per‑page averaging smooths out day‑to‑day and seasonal variation that a time‑aware model would need.
  • Feature depth: the model sees only numeric performance metrics — no text signal such as query intent, title wording, or content topic.
  • Threshold selection: the 2% CTR and top‑10 position cutoffs are fixed heuristics, not tuned to this dataset's actual distribution — which is very likely why the label came back empty here.
  • Sample size: results come from a partial pull of the warehouse, not the full release; findings here are directional, not a production‑ready model.
07

Ranked recommendations

1

Metadata & title rewrite

For any page that does clear a well‑tuned refresh threshold: rewrite titles to be more click‑worthy and align meta descriptions with the query intent already driving impressions.

2

Content freshness & intent alignment

For high‑impression pages sitting in positions 4–10: refresh outdated statistics, strengthen H2/H3 structure, and re‑align with current user intent.

3

On‑page engagement & internal linking

Add internal links from strong performers toward lower‑ranked, related content to help push borderline pages up toward position one.
